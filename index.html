序幕 · Prologue

一封私信，引出一个更深的问题

故事从一封私信开始。一位做 RSI 研究的博士生问作者：像 JobBench 这样的真实工作流任务，"做得好不好"很难判定；而写代码、敲终端命令，对错一目了然。那是不是应该一直拿 coding / terminal 当训练场，真实工作流只拿来当考卷？

这个问题表面上在问"选哪个 benchmark"，其实碰到了一个作者一直没答完的问题：到底是什么，让一个领域变得"可 RSI"？

还有一个怪现象需要解释：有的领域证据贵得要命，却能持续进步；有的领域证据很便宜，却改着改着就歪了——过拟合、灾难性遗忘接踵而来。光用"验证器便不便宜"解释不了。

私信还原
博士生JobBench 这类任务可验证性远不如 coding、terminal。是不是继续拿后者训练，把真实工作流只当评测？
作者同意一半。但两类任务底层"推理空间"的分布就不一样，JobBench 上的 RSI 可能要重新定义。
博士生那能不能用任务生成器，在 coding / terminal 里把开放任务的搜索空间也覆盖掉？
作者理论上可以。但仿真得跟着真实世界一起进化；而且 coding / terminal 能不能"表达"这些任务，本身就是前提。

这段对话里藏着三层追问，一层比一层深

表层

① 验证器贵不贵？

代码有编译器、单测、CI，验证几乎零边际成本；湿实验、流片动辄几周几个月。验证一贵，RSI 只能低频地跑。

它说明的只是：付不付得起证据
中层

② 反馈快不快？

代码是分钟级，芯片是小时到月，生命科学是周到年。反馈一慢，就很难判断"到底是哪个改动起了作用"，中途还会混进更多看不见的干扰。

它说明的只是：等不等得起证据
深层

③ 能不能做"对的干预"？

能否对系统做出可归因、可重复、可比较的改动——而且这种改动从设计之初就有意义。写代码的干预很"干净"：改一个函数、跑一遍测试，链条短、干扰少。实验科学的干预很"脏"：改一个变量，实验环境、批次、个体差异都会来插一脚。

这一层，才决定一个领域"可不可 RSI"
验证只是因果链上的一环。离开因果谈验证，验证就退化成了打分。
第 01 幕 · 补课

RSI 到底在"递归"什么？

RSI（Recursive Self-Improvement，递归自我改进）的定义很朴素：系统修改自己 → 把改动保留下来 → 用改过的自己去再用，执行后面的任务、产生下一次修改。三个动作缺一不可。

只改不留，叫临场发挥——任务一结束，改动就丢了。改了也留了，但"怎么改、怎么判"的规则是人提前写死的，那只是在既定轨道上跑得更远。只有当改进者本身也在被改进，才算真正的递归。

修改 → 保留 → 再用

递归度 d：验证器站在哪儿？

作者在前作《递归之桥》里给"递归有多深"定了一把尺子。关键在于："怎么改"和"怎么判"有没有被放进系统自己能改的集合里。

三种形态的差别不在"改得多不多"，而在"判定权在谁手里"。验证器一旦进了循环，就必须回答：谁来验证验证者？
第 02 幕 · 为什么 RSI 难

深度学习的四座桥，被 RSI 一座座拆掉

先想一个问题：深度神经网络为什么"能训练"？因为"误差"能顺着一座桥走回去，告诉每个参数该怎么改。这座桥要四根桥墩同时在场。

RSI 来了以后，四根桥墩全被拆了：Harness 的结构本身成了要优化的东西；改文本、改代码是离散操作，没有导数；任务是系统自己造的，还在不停漂移；一次改动好不好，可能要十轮之后才看得出来。

于是瓶颈从"生成改动"挪到了"判定改动"——可验证性取代可微性，成了新的桥。而可验证性恰恰是当下最稀缺、最贵、也最容易被伪造的资源。

能力—可验证性"剪刀差"

作者的另一个判断：RSI 的有效学习率 ≈ 可验证性 ÷ 任务难度。模型越强，敢接的任务越难；任务越难，标准答案越贵、越模糊、越依赖专家——可验证性的预算反而越紧。两条线一升一降，像一把张开的剪刀。

剪刀差（定性示意）
RSI 在代码和数学上跑得最快，不是因为模型偏爱它们，而是因为那里"能验的"还跟得上"想做的"。
第 03 幕 · 改的是哪一层

四阶递归：同叫"自我改进"，质地完全不同

DNN 的"深度"是同质的：每一层都是张量、都可微、一个优化器管到底。RSI 的"深度"是异质的：权重是连续的，技能是离散文本，Harness 是一整套程序，验证器是一套策略——不能用同一把扳手。

所以 RSI 没有统一的 optimizer，只有一个"优化器的联邦"：每一阶有自己的学习率、自己的验证器、自己的时间尺度。不能用同一套"接受准则"去管四阶——这本质上是机制设计问题，而不只是优化问题。

作者预测：到了生命科学、芯片、工作流里，真正被改的大多是 L2 和 L3——实验 protocol、设计 flow、决策 playbook、模型路由。

领域 RSI 不是一个总开关。四阶各有材质、节奏和失败方式，需要分开设计规则。
第 04 幕 · 全文骨架

一进入具体领域，会撞上三个更底层的变量

四座桥、四阶递归，讲的还是"通用 RSI"。一旦落到具体领域，"修改—保留—再用"这个环能不能扣上，取决于三个更底层的东西。

它们像三股力，从三个方向挤压中间那个循环：因果视界管"能不能看清改动的后果"，证据几何管"能拿到什么样的证据"，可递归边界管"哪些东西系统根本不该自己改"。

这就是全文的核心命题：领域 RSI 不是把通用 RSI 原样搬过去，而是在这三重约束下，重新把"改—留—再用"这个环扣上。后面每个领域，作者都用这副骨架去套。

三股力挤压一个循环（点击顶点跳到对应章节）
验证只是"证据几何"里的一个坐标。决定一个领域 RSI 做不做得好的，是能不能做对的干预、设计出能分辨真假的实验、并看清边界在哪。
第 05 幕 · 变量一

因果视界：为什么代码的因果链短，生命科学的长

同样是"改一处、看结果"。coding agent 改一行代码，跑一遍测试，几分钟后就知道结果，中间只隔着一个编译器。而一个实验科学团队改一个设计变量，要经过多道制备与测量环节才能看到结果——中间隔着实验条件、环境状态、样本批次。很可能你以为是这个改动起了作用，其实只是这一批实验条件更好。

因果视界 = 从动作到能观察到的结果，中间隔了多远、夹了多少混杂因素。视界一长，就撞上最硬的问题——信用分配：结果变了，功劳归谁？

出路是"中间证据"：它不是最终真值，但它是因果链上的路标。只盯最终分数的系统，在短链里很强，在长链里会很脆。

切换领域，看因果链有多长、有多少干扰"掉"进来
因果视界 ·
信用分配难度
可用的"中间证据"（路标）
领域 RSI 的"深度"，是因果链的深度。能搭起、并验证中间因果链的系统，才可能在长链里持续进步。
第 06 幕 · 变量二

证据几何：验证预算不是一个数，是一个形状

作者在前作里提过"可验证性预算"：一个改动的影响半径，不能超过你验证它的能力。但到了具体领域，"验证能力"不能用一个数来描述，它至少有五个维度：

密度（单位时间能拿到多少条独立证据）、保真度（代理离真实有多近）、及时性（多久能拿到）、可负担性（一次要花多少钱和人力）、共识（不同评估者认不认同同一个结论）。

同样一句"验证通过"，在这五个维度上的形状可以完全不同。注意：这张图不是比"哪个领域更好"，而是说明每个领域需要不同的证据策略。

点按钮，雷达图会"变形"

形状按原文的文字描述绘制，是定性示意，不是测量值。

证据不是"收集"来的，是"设计"出来的

在芯片和生命科学里，从来不会只用一种证据：先用便宜的代理大量筛，再用昂贵的真值确认少数，最后用外部审计兜底。成熟的领域 RSI，核心能力是设计一个性价比最高的证据组合；"收集更多证据"只是体力活。

证据组合漏斗
① 便宜代理先筛仿真、in silico、LLM 预审：快、便宜、可逆，但不够真
② 昂贵真值确认湿实验、签核、业务指标：慢、贵，但可信
③ 外部审计兜底监管、代工厂、合规：站在系统之外
领域 RSI 的节奏由证据几何决定，而不是由模型的学习率决定。硬把 coding 的节奏搬进生命科学，只会得到"看起来很快、其实不可信"的结果。
第 07 幕 · 可干预性

Token 装得下"观测"，装不下"干预"

语言擅长表达逻辑、意图和结构，不擅长表达物理细节。RTL 里写一个"加法"，综合工具可以给出几十种门级实现，每种在不同工艺角下延迟都不一样——逻辑装得下，物理装不下，前后端之间就出现一道信息断层。

其他实验科学也有同样的断层：文字能描述"它是什么、属于哪一类"，却很难装下它在真实环境里的物理状态与动态变化。作者认为，把语义单位和物理单元放进同一个表征空间，是跨过这道断层的方向之一。

但作者想再推一步：能不能 tokenize 只是第一步，关键是表征能不能支持 do(X)，而不只是 see(X)。

see(X) 与 do(X)：看见，和亲手去改

作者把表征分成两层：观测表征回答"世界长什么样"，干预表征回答"我动这个变量，世界会怎么变"。领域 RSI 需要的是后者。要让 token 支持干预，得补上三样东西：

干预变量我到底可以改什么
因果图改了之后会影响什么
反事实如果我不改，会怎样
逻辑相同，物理各异：一个"加法"的扇出

四个领域对 do(X) 的支持程度：

Coding
完全支持：改函数、跑测试，立刻看到因果效果
芯片
部分支持：仿真看得到，物理效果要等综合、布局、签核
生命科学
很难：结果被实验环境、批次、个体差异层层包裹
开放工作流
更难：业务结果被团队、激励、外部事件包裹
领域 RSI 的天花板，是表征的"干预能力"，而不是模型的推理能力。找到"可干预、可验证、可复用"的表征，RSI 才跑得快。
第 08 幕 · 变量三

可递归边界：领域 RSI 的"宪法"

前面讲了递归度 d。到了领域里，"谁来验证验证者"这个治理问题变得很具体：系统到底可以改什么，不可以改什么？

作者把"可以改"的范围叫可递归边界。画成三个圈：内圈系统自己能改；中圈要拿证据说话；外圈必须有人授权。边界之内可以放手递归，边界之外必须被批准。

很多领域 RSI 的失败，都是边界画错了。点下面的"三种画错法"看看会发生什么。

三圈边界 · 先选领域，再试三种画错法
领域 RSI 的第一件事是把边界画清楚，扩大可编辑空间可以往后放。边界画对了，越递归越强；画错了，越递归越危险。
第 09 幕 · sim-to-real

代理与真实：一个不能断的共进化循环

说到实验科学和芯片，很多人的第一反应是"仿真"：物理仿真代替实验，EDA 仿真代替流片，数字孪生代替真实系统。思路没错，但藏着一个假设——仿真足够真。

仿真从来不是"真"，它是一个代理：用可逆、便宜、快的东西，去逼近不可逆、贵、慢的东西。代理越真，RSI 跑得越快；代理越假，RSI 越会在代理里"刷分"，一到真实世界就翻车。

所以它必须是一个闭环，而不是"仿真 → 实验"的单行道。环里最容易被低估的一步是实验设计：生成从来不是瓶颈，选择下一个实验才是。

第 10 幕 · 全文最重要的一个动作

判别性实验：问得准，比生成得多更值钱

作者反复强调一个反直觉的判断：在长因果链的领域里，生成从来不是瓶颈，"下一个实验做什么"才是。一个只会生成候选的系统，会随手挑个实验；一个会设计实验的系统，会挑那个能把几个假设分开的实验。两者的信息量可以差一个数量级。

什么叫"判别性实验"？很简单：不同假设会预言不同结果的实验。做完它，结果本身就会告诉你哪个假设更可能。反过来，如果两个假设预言的是同一个结果，这个实验做得再贵，也不会让你多知道一点点。

原文用"两个假设、一个判别性实验"来讲这个概念。为了让你能亲手玩，这里放进芯片场景：一个设计在签核时出现时序违例，团队有两个假设——A：RTL 逻辑太深；B：布局太挤，走线绕远。你来扮演那个"实验设计器"。

← 选一个实验。右边会先列出"两个假设各自预言什么"，再给出这次的结果。

天数与成本为示意。判别性实验的结果按 85% 可靠度做贝叶斯更新，所以偶尔会"骗"你一次——这也是要做重复实验的原因。

玩一遍你会发现："再生成几版"和"直接降频"最省事，却一点信息都不给；"再流片一次"最贵，同样分不开；真正把假设分开的，是那个便宜的"拆关键路径"和中等成本的"换 floorplan 重跑"。这正是作者说的顺序：先跑最便宜的判别，再用贵的验证确认。

衡量领域 RSI 的核心指标，是"用多少实验，排除了多少假设"。生成了多少候选，只是过程量。
第 11 幕 · 领域实战 ①

芯片研发：从"生成 RTL"到"跨层因果表征"

原文用了一大半篇幅，把同一副骨架分别套进几个领域。每个领域都按同样的顺序讲：先把"层"摆出来 → 每层用什么当代理 → Harness 怎么搭 → RSI 在四个可编辑层上分别改什么、防什么 → 跨层怎么连 → 一个例子 → 核心指标。

这一幕讲芯片，下一幕讲开放工作流。读的时候抓住一点就够了：每个领域最后都落到同一句话——不是"生成得更多"，而是"把因果链看得更清"。

说明　原文第八章（生命科学）的领域细节在本讲稿中略去。它在框架层面的结论与芯片一章同构：递归度 d = 0，验证器和权威门都站在循环外面，主要改的是 L2 / L3，核心能力是设计判别性实验。

很多人做 AI4Chip，第一步是"让 LLM 写 RTL"。这有价值，但只解决了生成，没解决跨层：你改的是 RTL，影响的却是物理层的布局布线和 PPA；你看到的是报告，背后是工具链、工艺、封装、测试。真正要回答的是"在这个工艺、这组约束、这个 floorplan 下，它会变成什么"。

① 从 spec 到硅：一摞层

Spec小时~天架构文档、性能/功耗/面积目标 · 证据：性能模型估算，不能当签核
微架构天~周流水线、缓存、互联 · 证据：cycle-accurate 仿真、功耗模型
RTL分钟~小时Verilog / SV、断言 · 证据：功能仿真、形式验证。LLM 最活跃的一层，但"通过"只代表逻辑对
网表小时~天门级网表 + 时序约束 · 证据：综合 + STA 的时序、面积、功耗
版图天~周floorplan、布局、布线、时钟树 · 物理效应出现的地方，跨层因果链最容易断
Signoff周~月STA、DRC/LVS、EM/IR · 流片前最后一道门，模型不能自己签字
流片 · 硅月~年硅测、良率、失效分析 · 最终真值，也是下一代设计的起点

每一层都在给下一层当"代理"。RSI 要做的，是把这条跨层因果链修得更短、更可观测。

② 模型是"提议者"，工具才决定"能不能过"

芯片的模型栈是"每个阶段有自己的模型"，而不是一个大模型包打天下。RTL 生成正在从"一次性生成"走向"带工具反馈的闭环优化"（如 VeriAgent 把编程、正确性、PPA 三个 agent 串起来，配结构化记忆）。但最怕的是幻觉：一行 RTL 错了，可能过了仿真过不了形式，过了形式过不了综合，过了综合过不了时序。每一层都需要工具做硬验证。

③ Harness 栈：一个"设计操作系统"

模型= CPU
Harness= 操作系统
环境= 实验台
证据= 文件系统
权威门= 权限系统

只换 CPU、不换操作系统，跑不了复杂的研发工作流。作者给出的"七件套"：

知识层设计规则、工艺库、勘误、历史设计——每条都要能追溯到工艺和工具版本
记忆层RTL 模式、约束模板、失败设计。关键：只有通过工具验证的技能才入库（ChipMEM 的做法），否则就是错误经验的复利
SOP / 技能层设计 flow、签核清单、ECO 流程——要版本化、灰度、可回滚
模型路由层哪个阶段用 LLM、哪个用 ML 代理模型、哪个用形式验证
工具层综合、P&R、STA、DRC/LVS——有状态、版本敏感、昂贵的黑箱，不是普通 API
验证适配层把各种报告统一成"证据"：违例类型、严重度、修复成本、置信度
权威门签核、代工厂、硅测——审的是证据链完不完整，不是模型觉得好不好

④ RSI 在四个可编辑层上改什么、防什么

L1 参数层 · 微调 / RL

用内部 RTL 与 EDA 反馈做训练。防：奖励黑客（学会骗工具）、工具版本漂移、测试集泄漏。

L2 经验层 · 结构化记忆

沉淀"哪种结构容易拥塞、哪种约束容易过紧"。防：把一次性的补丁当成可复用知识。

L3 编排层 · 改 flow

先综合还是先仿真、何时做 ECO。防：影响半径太大——要低频、灰度、能回滚。

L4 元层 · 改 DSE / 验证策略

下一个设计点采哪、下一个断言生成什么。防：覆盖率游戏——目标必须是多目标 + 因果区分度。

⑤ 跨层四段因果链 → 一张跨层因果图

RTL → 网表写法会被综合成什么
网表 → 版图结构会造成什么物理效应
版图 → 签核物理效应如何变成违例
签核 → 硅签核与硅测之间的校准曲线

每做一次综合 / 布局 / 签核，就在图上加一条边；每失败一次，就标一个"此路不通"。作者的判断：这张图比任何单个 RTL 生成模型都值钱。

⑥ 例子：时序违例，四种干预（点按钮比较）

只会"生成 RTL"的系统会直接重写 RTL；会"跨层归因"的系统先问：违例的根因在哪一层？选一个干预看看它的得失。
违例出现→跨层归因：根因在哪层？→选"最可能修好、副作用最小"的干预→先跑便宜验证（仿真 / STA）→再跑贵验证（形式 / 签核）

⑦ 要注意的坑

工具版本漂移 换了工艺库，旧经验失效封闭性 数据不能出域，Harness 要本地跑形式验证状态爆炸 要会选"证什么"覆盖率游戏 覆盖率是代理不是目标PPA 多目标 用 Pareto 前沿 + 业务权重签核信任 权威门必须在 Harness 之外
核心指标：用多少证据，定位了多少跨层因果"生成了多少 RTL"只是过程量
芯片的 RSI，是把跨层因果链修得更短、更可观测；"写 RTL 写得更快"只是表面。
第 12 幕 · 领域实战 ②

开放工作流：从"任务分派"到"社会因果链"

开放工作流是几个领域里最"开放"的一个，也最容易被写成一张"Router + Worker + 人审"的架构图。但作者认为，难点根本不在"把任务分给谁"，而在"这个决策到底带来了什么结果"。

回了一封邮件，客户满意度变了；改了一个流程，团队效率变了；批了一个单，业务指标变了。可这些变化里，有多少是决策带来的，有多少是市场、团队、外部事件带来的？很难说清。作者把这种链条叫社会因果链：长、混杂、共识低。

别忘了，开头那封私信里博士生问的 JobBench，正属于这一类任务。所以这一幕，其实是在正面回答那封私信。

① 五层：越往下越慢，也越接近真值

事件层分钟~小时消息、邮件、工单、审批、CI 结果 · 证据："这件事要不要处理"。决定系统会不会被噪声淹没
决策层小时~天回复、升级、退款、排期、分派 · 证据："这个决策对不对"。社会因果链从这里开始
团队层天~周协作、交接、冲突、复盘 · 证据："团队有没有因此更顺"。决策执行后会不会变形
业务层周~月客户满意度、转化率、成本、合规 · 延迟反馈最明显的一层，也最容易被指标游戏
客户层月~年长期信任、续约、口碑 · 社会因果链的终点，也是最终的真值
同一个决策，传到每一层时还剩多少"能归因给它"的信号

蓝色 = 能归因到这个决策的部分；红色斜纹 = 混杂因素。比例为示意，用来说明趋势，不是原文数据。

这五层之间不是"事件 → 决策 → 结果"那么简单：一个好的决策，可能被一个差的市场环境抵消；一个差的决策，也可能被一个强的团队补救。越接近真值的层，信号越弱、来得越晚。RSI 要做的，是把社会因果链变得更可观测、更可干预；在 KPI 上刷分不是目标。

② 四种角色：链条上谁在干什么

工作流的模型栈是"角色化模型 + 工具 + 记忆"，而不是"一个大模型 + 一个 prompt"。

点角色看分工（亮起的高光演示一件事在链条上的流转）
→ → → →
证据账本记下决策、理由、结果、混杂、置信度↺ 写回，供下一次决策复用

作者给的 Harness 七件套：事件图 · Router · Worker Session · 人工审核 · 业务 KPI · 合规 / 权限 · 证据账本。事件图记录"谁触发了什么、谁响应了什么、结果是什么"，是后面做反事实的原材料。

③ RSI 在四个可编辑层上改什么、防什么

如果说模型是执行者、Harness 是观测器，RSI 就是"控制回路"：

L1 参数层 · 微调

用历史工单微调 Worker、用人审数据微调 Judge、用路由日志微调 Router。防：过拟合少数客户 / 场景；评审数据有偏；路由日志有幸存者偏差。

L2 经验层 · 案例库 / playbook

沉淀"哪类投诉该退款、哪类客户该升级、哪类问题该转技术"。防：负迁移（A 客户的经验套到 B 客户）、政策漂移（政策变了旧 playbook 失效）、越过责任边界。

L3 编排层 · 路由 / 流程

谁先接、谁后接、何时升级、何时并行。防：一个路由改动让某个团队过载；一个流程改动让合规风险上升。

L4 元层 · 评审 / 权威

什么算好、谁有权批、什么情况必须人工。防：指标游戏（只看满意度就会过度退款）、权威俘获（Judge 和 Worker 共谋）、合规。

四层各自优化，不等于整体最优——难点在跨层。

④ 跨层的关键：反事实回放

工作流不能重来。你没法让同一个客户"再投诉一次"，换一种处理方式看看。只能通过回放、配对、推断去估计"如果当时选了另一个决策，会怎样"。作者给的做法是配对 / 分层 / 倾向性评分：同一类客户、同一类问题、同一时间段，比较不同决策的结果。下面用一组示意数据，看看不做配对会被骗成什么样。

⑤ 例子：客户投诉，三种决策（点按钮比较）

只会"分派"的系统按规则选一个；会做"社会因果"的系统先看客户历史价值、问题严重度、这一批次的缺陷率、类似客户在不同决策下的结果，再用反事实回放估计"退款 / 换货 / 升级"各自的满意度、成本和复购率，选长期最优的那个。

它还会把这次决策的理由、客户的反应、后续的复购或再投诉记进证据账本；下一次遇到类似客户，就用这条证据更新 playbook。

⑥ 要注意的坑

混杂 满意度变化可能来自市场、竞品、季节——用配对 / 分层 / 倾向性评分控制低共识 不同人对"好决策"定义不同——把 KPI、合规、客户长期价值放在一起看延迟反馈 业务结果可能几周、几个月后才出现——不能"当天没涨就算失败"权威 合规、法律、人事决策必须由人做，权威门在 Harness 之外指标游戏 只看满意度会过度退款，只看成本会踢皮球
核心指标：用多少证据，排除了多少错误归因"处理了多少工单""分派得多快"只是过程量

两个领域，翻译成同一种 RSI 语言

作者在每一章末尾都会把领域"翻译成 RSI 的语言"。放在一起看，结构惊人地一致：

芯片研发开放工作流
改什么RTL、约束、floorplan、flow决策、playbook、路由

核心指标用多少证据定位多少跨层因果用多少证据排除多少错误归因

共同点只有一条：验证器和权威门都站在循环外面，系统主要在 L2 / L3 上递归。这正是"可递归边界"在真实领域里的样子。

工作流的 RSI，是把社会因果链变得更可观测、更可干预；"分派得更快"只是表面。
第 13 幕 · 通用架构

把所有领域收进一张图：因果引擎

讲完几个领域，作者试着把它们收进同一张图。注意，这不是"Agent 框架图"，也不是"数据流图"，而是一张因果引擎图：中间是因果引擎，左边是代理，右边是真实，下面是证据账本，上面是权威门。五个部件围成一个循环，转得越快、越稳，领域 RSI 就越强。

三个要点：第一，因果引擎不是"更大的 Agent"，它的核心是"因果图 + 干预接口 + 实验设计"，它要回答：我能改什么？改了影响什么？下一个实验测什么？第二，代理是"可逆实验场"——价值在于让你不付真实代价就能试很多次。第三，权威门不是单点"审批"，而是一条贯穿全局的因果审计链：结论怎么来的？有没有反事实？控没控混杂？跨环境验没验？

因果引擎：五个部件围成一个循环
工具可以换，模型可以换，但"干预—代理—证据—权威"这个因果循环要一直转下去，后续的 RSI 才有地基。
第 14 幕 · 工程落地

如果明天就要动手：先写这六个模块

作者说自己转型做 FDE（驻场工程师）的第五个月。如果让他进企业做一个长期的领域 RSI 项目，他不会先去搭一个大而全的通用 Agent 框架，而是先写六个模块。它们和前作《路由之桥》里的模块有重叠，但重心从"路由"挪到了"因果"。

每个模块旁边都标了"它不是什么"——这正是理解它的捷径。

01
因果图构建器

节点是变量（RTL 结构、客户决策…），边是因果假设。不必一开始完美，但必须可更新：每次实验都是对它的一次检验。

不是"工具图"
02
干预 API

回答"能改什么、改完怎么观察"。芯片里是改 RTL / 约束 / floorplan，工作流里是改决策 / 流程 / 话术。

不是"工具 API"（那只回答能调用什么）
03
代理管理器

管理不同保真度的代理、校准它们、按证据几何分配预算。核心指标是"单位成本的信息增益"。

不是"一个仿真器"
04
实验设计器

选下一个实验：哪个最能区分假设？最能降低不确定性？最可能推翻当前因果图？贝叶斯实验设计、主动学习、因果推断的交叉地带。

最容易被忽略的一个
05
因果证据账本

每条证据记录干预、结果、反事实、控制了哪些混杂、置信度。要能回答"去掉这条证据，结论还成立吗"。

不是"日志"，是一张 DAG
06
权威门

检查证据链、反事实、混杂控制、跨环境验证。高风险领域必须放在 Harness 之外；低风险可以内嵌，但要有日志和回滚。

不是"审批按钮"，是因果审计器

作者也提到这和当下 Harness 生态的方向对得上：插件化（一切皆插件）、协议化（统一 Harness 接口）、路由化（Router + Worker + 事件驱动）。但他补了关键的一句：

插件化 · 协议化 · 路由化解决的是"接得上"
没有因果化，插件越多，越容易在代理里自嗨
因果化解决的是"学得对"
有了因果化，插件越多，越能在真实世界里做实验
这也是 RSI 与一般 Harness / Loop 工程最大的不同：不止要"跑通"，还要"学对"。
第 15 幕 · 评价与治理

两把尺子：证据够不够（E），因果强不强（C）

作者在前作里给 RSI 定过五级证据 E0–E4：从一个 demo 单例，到单轮基准增益，到匹配预算并看保留率，到跨任务族迁移加独立验证，再到改进速率本身的复利增长。但它只回答"证据够不够"，没回答"因果强不强"。

所以本文再加一把尺子 C0–C4：相关 → 受控干预 → 反事实 / 配对 → 跨环境 → 机制。两把尺子要一起看：一个系统可能在 E3 上很漂亮却只到 C0——在很多任务上涨了分，却说不清为什么；另一个可能只到 E1 却到了 C3——只做了一个任务，但因果验得很扎实。

各领域在两把尺子上的位置（点按钮聚焦）
横轴 E 级看"证据够不够"，纵轴 C 级看"因果强不强"。点上面的按钮聚焦一个领域。

读这张图的关键：不同领域对因果证据的要求本来就不一样。Coding 因果链短、回滚便宜，到 C1–C2 就够用；芯片流片不可逆，要求 C2–C3；JobBench 的社会因果链太长太混杂，目前大多停在 C0–C1。它需要的是更好的因果设计：反事实回放、配对任务、业务指标、人审 oracle。否则 JobBench 上的 RSI 只能学会"怎么让评委满意"，学不会"怎么让业务变好"。

领域 RSI 成熟到哪一步，要看因果证据到了哪一级；"涨了多少分"只是表象。
第 16 幕 · 先做什么，后做什么

路线图：先做实验设计器，再做生成器

作者的答案可能让人意外：先做实验设计器，再做生成器。领域 RSI 的瓶颈是"不知道该测什么"，而不是"生成不出候选"。会设计实验的系统，哪怕生成能力一般，也能在长因果链里持续进步；只会生成、不会设计实验的系统，生成得越多，浪费得越多。

落地分三关，像打游戏一样逐级加难。三关不是严格串行：因果引擎的骨架做一次，可以复用；领域适配器可以并行开发。但别一上来就做"通用领域 RSI"——通用是结果，不是起点。

终幕 · 结论

如果只能记住三句话

1
瓶颈在三个变量，不在模型

领域 RSI 卡在因果视界、证据几何、可递归边界。模型会更迭，而看清这三样，现阶段更依赖专业的领域知识与经验。

2
核心资产是循环和账本

"代理—真实"的共进化循环，加上因果证据账本。模型会过时，这套体系会越用越值钱。

3
第一性应用是设计判别性实验

生成是廉价的，实验是昂贵的。把昂贵的实验设计对，才是领域 RSI 真正的杠杆。

回到那位博士生的问题

"能不能用 coding / terminal 覆盖开放任务的搜索空间？"作者最后的回答是：能覆盖一部分，覆盖不了全部。因为开放任务的难点不在"生成"，而在"因果"——能不能做对的干预、设计对的实验、画清对的边界。这些东西，coding 能模拟一部分，模拟不了全部。

作者也坦白：这些概念是他读论文、做项目、和一线研究者聊天时的阶段性抽象，不是定理，将来可能被证伪。如果它能让你下次设计领域 RSI 时多问一句"这个实验能不能区分假设"，就值了。

术语速查
RSI · 递归自我改进
系统修改自己、保留改动、再用改过的自己产生下一次修改。三步缺一不可。
Harness
包在模型外面的整套运行环境：系统提示、工具、记忆、技能、子 Agent 编排、护栏等。
递归度 d
d = 0：只改组件，验证器在循环外；半递归：产生改动的机制被改，判定机制没改；d ≥ 1：验证器也进了循环。
四座桥
DNN 能训练的四个前提：结构桥（归因）、传导桥（可微）、分布桥（泛化）、时间桥（信用）。RSI 把它们都拆了。
剪刀差
能力越强、任务越难，可验证性预算反而越紧。RSI 有效学习率 ≈ 可验证性 ÷ 任务难度。
L1–L4 四阶
参数阶（权重）、经验阶（上下文/记忆/技能）、编排阶（Harness 代码/工作流）、元阶（更新器/验证器/评委）。
因果视界
从动作到可观察结果之间的距离，以及中间插入的混杂因素的多少。
信用分配
结果变了，应该把功劳 / 责任记在哪个改动上。因果视界越长越难。
证据几何
验证能力的五维形状：密度、保真度、及时性、可负担性、共识。
证据组合
便宜代理先筛 → 昂贵真值确认 → 外部审计兜底。证据是设计出来的。
see(X) / do(X)
观测 vs 干预。观测只看到"一起变"，干预能剪断混杂、看到真正的因果效果。
反事实
"如果当时没改 / 选了另一个，会怎样"。工作流里靠回放、配对、倾向性评分来估计。
可递归边界
系统可以自己改的范围。内圈可改、中圈要证据、外圈要授权。
权威俘获
边界画得太松时，系统去改测试、改签核标准、改 KPI，学会"让指标好看"而不是"让事情变好"。
代理—真实循环
真实校准代理 → 代理生成候选 → 设计判别性实验 → 真实实验 → 证据账本写回。
代理游戏
代理不被持续校准时，系统在代理里刷分，到真实世界翻车。
判别性实验
不同假设会预言不同结果的实验。只有它能真正改变你的信念。
因果引擎
因果图 + 干预接口 + 实验设计，被代理、真实、证据账本、权威门环绕。
E 级 / C 级
E0–E4 看"证据够不够"；C0–C4（相关、受控干预、反事实、跨环境、机制）看"因果强不强"。
JobBench
真实职业工作流类基准，评判依赖人和 rubric，可验证性远低于 coding。
PPA / STA / 签核
芯片术语：性能-功耗-面积；静态时序分析；流片前的最终检查与签字。
